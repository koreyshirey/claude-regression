What this measures §1

Claude Code writes every session to disk as JSONL, timestamped, with the model recorded per message. That makes a personal, longitudinal dataset: not benchmark scores, but what actually happened across two months of real work — homelab automation, PCB design, firmware bring-up, media infrastructure.

The comparison is claude-opus-4-8 (dominant through July) against claude-opus-5 (dominant in August). Everything is normalised per request — one thing I asked for — rather than per message, because opus-5 emits 31.4 assistant messages per request against opus-4-8's 25.7. Dividing by messages hides the effect behind the model's own verbosity.

The core proxy for "it made a mistake" is an admission that credits the human — Claude saying "you're right" or "good catch". It cannot say that unless it was just contradicted. Across every model, 62–70% of all admissions are of this kind, so admissions track caught errors rather than spontaneous self-doubt.

Verdicts §4

Supported

Mistakes I have to catch roughly doubled

Two methods that share no assumptions agree. Automated admission-counting gives ×2.09 (p = 0.000075). Hand-labelling 100 randomly sampled exchanges — with the model identity withheld from the labeller until after every label was fixed — gives ×2.67 (p = 0.007). Roughly one in three requests to opus-5 now involves correcting, objecting, or restating.

Supported

It costs more, and I supply more of the context

Median output tokens per request rose 51% (p = 0.0012) and tool calls per request rose 80% (p = 0.0079). The share of all generated tokens spent inside requests that end in a concession went from 19.5% to 30.9% — nearly a third of output now goes to exchanges that end in "you're right."

Meanwhile the characters I type per request rose 67% (p < 0.0001). Front-loading more context is not preventing the friction; both went up together.

Not supported

I am not repeating myself more

This was the claim I was most confident about, and the data does not back it. Hand-labelled restatement went from 6% to 8% of requests — p = 1.0. Nothing there.

One real blind spot: the labeller saw only two prior turns within a single session, so re-teaching the same lesson in a new session is invisible to this method. That is a different measurement, and it has not been built yet.

Unmeasurable

Reasoning quality cannot be assessed at all

Thinking content is stored as an empty string plus an encrypted signature for every model except sonnet-4-6. There is no reasoning text to measure. Any claim that "thinking got shorter" would be an artifact of a storage policy change, not a finding.

Behavioural proxies for flailing all came back null: self-reversals p = 0.76, failed edits p = 0.97, duplicate commands p = 0.85, repeated file reads p = 0.10 and moving down. More tokens and more tool calls per request are equally consistent with thoroughness and with churn; nothing here separates them.

Method §5

Everything is computed from local transcripts by a script that re-reads them live; no numbers are hand-entered. Three guards matter:

  • Blind labelling. The sample file carries no model name and no date. Labels were committed before the key was opened. Grading with the answer visible would invalidate the entire result.
  • Fisher exact, not the z-test. On small counts the normal approximation lies. It called a 0/292 vs 2/149 split significant at p = 0.047; Fisher gave p = 0.11. Two headline numbers were nearly published wrong this way.
  • Per-request denominators. Rates per assistant message flatter a verbose model. The unit is the thing a human asked for.

Limitations — read before citing this

Model and date are the same variable. Model assignment was never randomised: opus-4-8 dominates July, opus-5 dominates August. Anything that changed over calendar time is indistinguishable from anything that changed with the model.

Task mix shifted. The opus-5 sessions skew toward harder debugging, where errors are likelier regardless of which model is running.

The labeller was Claude. Blinding removes the model identity, but writing style may still leak the answer. An independent human labeller on the same sample would settle it.

The headline metric measures admission, not error. A future model that concedes less readily without actually improving will look like progress on this chart. Periodic blind labelling is the only thing that catches that.

Run it on your own logs §6

One machine's transcripts cannot separate "this model got worse" from "this user's work got harder." More datasets can. The tooling is a few Python files with no dependencies beyond the standard library, and it never transmits anything — it reads ~/.claude/projects and writes locally.

python3 snapshot.py archives your transcripts and appends weekly per-model metrics. It takes about two seconds and is safe to re-run. What is worth sharing back is metrics_history.jsonl: counts only, no message content.

Before you share anything

Raw transcripts contain plaintext secrets. Mine held a wifi password, personal email addresses, and vault variable names — none of which I put there deliberately. The archive directory is gitignored for that reason. Never push it, and check what you are sending before you send it.

One setting is worth changing immediately whether or not you run any of this: cleanupPeriodDays defaults to 30, so your transcripts are on a rolling window that quietly deletes its own baseline. Mine was about three weeks from being unrecoverable when I checked.
